# PPGP Distribution

PPGP is intentionally distributed through multiple channels. The protocol and canonical Agent Skill remain vendor-neutral; platform-native manifests are thin adapters for discovery and installation.

Canonical protocol skill:

```text
skills/ppgp/SKILL.md
skills/ppgp/references/PPGP.md
```

For platforms that discover the cross-agent `.agents/skills/` convention, the repository also contains a generated byte-identical mirror under `.agents/skills/ppgp/`. `npm test` fails if that mirror drifts from the canonical skill.

Regenerate the compatibility mirror deterministically with:

```bash
node scripts/sync-skill-mirror.js
```

See [`COMPATIBILITY.md`](./COMPATIBILITY.md) for the current platform-by-platform support matrix and verification state.

## Universal Agent Skills route

Purpose: direct installation into Agent Skills-compatible environments without tying PPGP to a vendor.

```bash
npx skills add https://github.com/Fatboy-coder/ppgp/tree/main/skills/ppgp
```

This remains the preferred portable skill source.

## Anthropic Claude Code

PPGP exposes a Claude plugin and a self-hosted marketplace from the canonical repository:

```text
.claude-plugin/plugin.json
.claude-plugin/marketplace.json
```

Intended UI flow:

```text
Claude
→ Plugins
→ Add marketplace
→ Fatboy-coder/ppgp
→ Sync
→ install ppgp
```

Claude's standard plugin layout discovers the repository-root `skills/` directory automatically. The marketplace contains only the PPGP plugin. Repository structure is ready; the Claude UI installation remains an external smoke test.

## OpenAI Codex and ChatGPT

OpenAI plugins can package skills without requiring an app. PPGP therefore exposes a skill-only Codex/OpenAI plugin:

```text
.codex-plugin/plugin.json
.agents/plugins/marketplace.json
```

The Codex plugin explicitly uses the canonical `skills/` directory. The repo marketplace metadata makes the package consumable in Codex-compatible plugin workflows.

The same skill can be used as an OpenAI Agent Skill. ChatGPT and Codex now share the Plugin Directory model, but repository packaging does not mean PPGP is publicly listed by OpenAI.

States are kept distinct:

```text
repository ready
!= submitted
!= approved
!= publicly listed
```

Public Plugin Directory publication is an external vendor-side step.

## Google Gemini CLI

PPGP exposes a Gemini CLI extension manifest at repository root:

```text
gemini-extension.json
```

The extension reuses the canonical `skills/ppgp/` directory.

Intended install:

```bash
gemini extensions install https://github.com/Fatboy-coder/ppgp --auto-update
```

Repository structure is ready; a local Gemini CLI smoke test remains external.

## Cursor

PPGP exposes the open Agent Plugins format at repository root:

```text
plugin.json
```

The Agent Plugins specification keeps the manifest declarative while compatible clients discover conventional plugin content such as the repository-root `skills/` directory. PPGP therefore keeps `plugin.json` schema-safe and co-locates it with the canonical `skills/ppgp/` source rather than adding a proprietary semantic fork.

A separate `.cursor-plugin/plugin.json` is intentionally not added in v0.1 because PPGP currently needs only skills and the portable Agent Plugin format covers the intended distribution surface.

Cursor Marketplace publication is an external submission step and is not claimed as complete.

## GitHub Copilot

GitHub Copilot supports Agent Skills from `.agents/skills/` in repository scope. PPGP therefore commits a generated compatibility mirror:

```text
.agents/skills/ppgp/
```

This mirror is not authoritative. Tests enforce byte-for-byte parity with `skills/ppgp/`.

The same repository skill can be used across Copilot CLI, supported IDE agent modes, cloud agent workflows, and other Copilot surfaces that implement Agent Skills.

## Windsurf

Windsurf supports Agent Skills and recognizes `.agents/skills/` as a cross-agent compatibility path. The generated PPGP mirror therefore provides repository-native discovery without a Windsurf-specific semantic copy.

## Devin

Devin supports the open Agent Skills convention and recommends repository skills under `.agents/skills/`. The generated PPGP mirror provides repository-native discovery.

## Kiro

Kiro supports Agent Skills and public GitHub skill imports. Use the canonical public skill source:

```text
https://github.com/Fatboy-coder/ppgp/tree/main/skills/ppgp
```

No Kiro-specific copy is maintained.

## Cline

Cline supports Agent Skills. Use the canonical PPGP skill and install/copy it into a supported Cline skills location, or use a generic Agent Skills installer where available.

No Cline-specific semantic adapter is maintained.

## JetBrains Junie

Junie supports Agent Skills. PPGP remains consumable from the canonical skill through Junie's supported project/user skill import locations.

No Junie-specific semantic adapter is maintained.

## Secondary-platform policy

For Roo Code, Amazon Q Developer, and other agent platforms, PPGP only adds a native adapter after the platform exposes a stable, documented mechanism that can be tested without forking protocol semantics.

Until then, the canonical Agent Skill and CLI remain available, and `COMPATIBILITY.md` records the exact current support state rather than inventing proprietary files.

## GitHub Release

Canonical asset:

```text
ppgp-v0.1.zip
```

## npm

Purpose: public CLI discovery and zero-install execution.

Canonical public package name:

```text
@fatboy-coder/ppgp
```

The original unscoped name `ppgp` is intentionally not used because npm's similarity protection rejects it as too close to existing high-traffic package names. The scoped package keeps the PPGP identity while avoiding namespace ambiguity.

CLI binary:

```text
ppgp
```

Zero-install examples:

```bash
npx @fatboy-coder/ppgp init
npx @fatboy-coder/ppgp doctor
npx @fatboy-coder/ppgp goal "Ship the next verified milestone"
npx @fatboy-coder/ppgp status
npx @fatboy-coder/ppgp handoff
```

Global installation keeps the shorter executable:

```bash
npm install -g @fatboy-coder/ppgp
ppgp init
```

The npm package also bundles the canonical Agent Skill. `ppgp install-skill <destination>` copies the bundled skill into an explicit destination without assuming a vendor-specific client path.

The platform adapter manifests added for Claude, Codex, Gemini and Agent Plugins are intentionally excluded from the current npm `files` list. This distribution iteration therefore does not require republishing npm 0.1.0.

### npm Trusted Publisher

The npm package is published under the scope:

```text
@fatboy-coder/ppgp
```

Trusted publishing is configured through GitHub Actions with OIDC. The workflow is `.github/workflows/publish-npm.yml`.

Traditional long-lived automation tokens should remain unnecessary after trusted publishing is established.

## GitHub Packages

Purpose: presence inside the GitHub package ecosystem and a package directly associated with the repository.

Published package name:

```text
@fatboy-coder/ppgp
```

The GitHub package is produced from the same npm package contents and published to GitHub's npm registry.

GitHub Packages is a secondary distribution surface. The public GitHub Release and npmjs.com package remain lower-friction universal entry points.

## Validation

`npm test` validates both the CLI and distribution invariants:

- canonical skill exists;
- Claude, Codex, Agent Plugin and Gemini manifests parse as JSON;
- adapter versions match `package.json` version `0.1.0`;
- marketplace identities point to `ppgp`;
- the Codex manifest points to the canonical `./skills/` directory;
- the root Agent Plugin manifest contains only schema-supported top-level fields and is co-located with canonical `skills/` content;
- `.agents/skills/ppgp/` remains byte-identical to the canonical skill and reference;
- platform adapter directories do not silently enter the npm package contents.

GitHub Actions runs the same test suite for pushes and pull requests.

## Version mapping

The protocol currently uses specification version `0.1`.

Package/plugin adapter manifests use semantic package version `0.1.0`.

```text
PPGP protocol 0.1
npm package @fatboy-coder/ppgp@0.1.0
GitHub package @fatboy-coder/ppgp@0.1.0
Claude/Codex/Gemini/Agent Plugin adapters 0.1.0
GitHub release v0.1
```

Adding distribution adapters does not create a new protocol version.
